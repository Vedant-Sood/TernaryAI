# Datasets, licensing and preprocessing

## Principles

* Every source is registered in `src/triforge/datasets/registry.py` with its Hub id, licence, role
  (train / eval) and caveats. Licences were read from the Hugging Face dataset cards via the Hub API on
  2026-10-26. A licence tag is the publisher's claim, not legal advice, and synthetic datasets generated
  by other models can carry extra terms from that model's licence.
* Benchmarks are **evaluation only** (`train_ok=False`) and are also used for n-gram decontamination.
* Non-commercial (NC) sources are excluded from default training mixtures.
* Each build writes `data/<specialist>/<version>/manifest.json`: sources, licences, revisions, filter
  counts, mixture weights, token counts, SHA-256 of each token shard, decontamination settings.

The synthetic generators produce verified problems (arithmetic chains, linear equations, gcd/lcm,
fractions, derivatives, word problems; kinematics, circuits, units, energy, momentum, waves,
work/power, propositional logic, syllogisms; Python output prediction and function implementation
checked by executing tests). Train and test come from disjoint seeds, and any test prompt is
removed from train.

## Processing steps (in order)

1. **Domain filter** (`keep_regex` / `drop_regex` per source).
2. **Malformed records** dropped: empty fields, length out of range, U+FFFD replacement characters,
   >5% non-printable characters. For code sources, `require_valid_python` drops responses whose
   ```python blocks do not parse.
3. **Exact duplicates** (SHA-256 of normalised prompt + response).
4. **Near duplicates**: MinHash (64 permutations, 16 bands, word 5-gram shingles) on the prompt, for
   natural data only (templated synthetic items share shingles by design).
5. **Benchmark decontamination**: drop any training example sharing a 13-word n-gram with a
   HumanEval / MBPP / GSM8K / MATH-500 / ARC test item (the GPT-3 / LLaMA protocol). If a benchmark
   cannot be downloaded, the build prints a warning and the manifest records that it was not used.
6. **Deterministic split**: hash-based train/val/test assignment, so it's stable across machines.
7. **Formatting and tokenization**: chat template (`triforge` for the small models, BitNet's
   `User: …<|eot_id|>Assistant: …` for 2B4T), loss mask = 1 on response tokens only, packed into one
   memory-mapped token stream per split.

## Commands

```bash
# CPU validation data (offline: synthetic + local stdlib), one shared 4k BPE tokenizer
python scripts/prepare_data.py --config configs/tricode/cpu_validation.yaml \
    configs/trimath/cpu_validation.yaml configs/trireason/cpu_validation.yaml

# 2B fine-tuning data (needs huggingface.co; streams the sources, BitNet tokenizer)
python scripts/prepare_data.py --config configs/tricode/bitnet2b_partial_rtx4060.yaml
python scripts/prepare_data.py --config configs/trimath/bitnet2b_partial_rtx4060.yaml
python scripts/prepare_data.py --config configs/trireason/bitnet2b_partial_rtx4060.yaml
```

Pin `revision:` on each source in the config to make a build bit-for-bit reproducible. Unpinned
sources are recorded as `main (unpinned)` in the manifest.
